# Seed 3D (Hyper3D and Hitem3d)

Load this when you generate a 3D model with `hyper3d_*` or `hitem3d_*`, poll
or persist the package, or hand it to Blender or another DCC tool.

Requires `BYTEPLUS_MODELARK_3D_ENABLED=true` and `BYTEPLUS_MODELARK_API_KEY`;
**disabled by default**. Scopes: `hyper3d:create`, `hyper3d:read`,
`hyper3d:delete`, `hitem3d:create`, `hitem3d:read`, `hitem3d:delete`. Inspect live tool registration or
`seed-health://status` first; documentation alone is not evidence that the
running server exposes 3D tools.

Lifecycle: `queued → running → succeeded | failed | cancelled | expired`.
Get, list, and cancel tools are **family-specific**: use `hyper3d_*` for
Hyper3D task IDs and `hitem3d_*` for Hitem3d task IDs.

## Choose the family

| Family | Model | Inputs | Choose for |
|---|---|---|---|
| Hyper3D | `hyper3d-gen2-260112` | Text and/or up to 5 images | Text-to-3D, seeds, PBR materials, Raw/Quad meshes, HD textures, bbox conditioning, T/A-pose |
| Hitem3d | `hitem3d-2-0-251223` | 1–4 images (image-to-3D only) | Multi-view input (front/back/left/right), resolution and face-count control |

## `hyper3d_create_task`

| Parameter | Notes |
|---|---|
| `prompt` | English, ≤ 400 characters; required for text-to-3D without images |
| `images` | Up to 5 |
| `model` | Omit for the default |
| `seed` | 0–65535 |
| `callback_url` | Optional status callback |
| `material` | `PBR` (default), `Shaded`, `All`, `None` |
| `mesh_mode` | `Raw` (triangles) or `Quad` (default) |
| `quality_override` | Polygon count (Raw 500–1M, Quad 1000–200K); overrides `subdivision_level` |
| `addons` | `HighPack` (4K textures) |
| `use_original_alpha` | Preserve transparent input areas |
| `bbox_condition` | `[width, height, length]` |
| `ta_pose` | Force T/A-pose for humanoids |
| `subdivision_level` | `high`, `medium`, `low` |
| `file_format` | `glb` (default), `obj`, `usdz`, `fbx`, `stl` |
| `hd_texture` | HD textures |

```json
{"tool_name": "hyper3d_create_task",
 "arguments": {"input": {"images": [{"kind": "url", "url": "https://cdn.example.com/character.png"}],
                         "material": "PBR", "mesh_mode": "Quad", "file_format": "glb"}}}
```

## `hitem3d_create_task`

| Parameter | Notes |
|---|---|
| `images` | 1–4, required |
| `model` | Omit for the default |
| `callback_url` | Optional |
| `resolution` | `1536` (default) or `1536pro` |
| `face` | 100000–2000000 |
| `file_format` | `obj` (default), `glb`, `stl`, `fbx`, `usdz` |
| `request_type` | `1` geometry only, `3` geometry + texture (default) |
| `multi_images_bit` | Views present in order front/back/left/right, e.g. `"1010"` = front + left |

```json
{"images": [{"kind": "url", "url": "https://cdn.example.com/front.png"},
            {"kind": "url", "url": "https://cdn.example.com/left.png"}],
 "multi_images_bit": "1010", "resolution": "1536pro", "file_format": "glb"}
```

Both create tools return `task_id`, `status="queued"`, and
`recommended_poll_after_ms` (5000).

## Workflow

1. Submit the create tool through `ark_job_submit`; record the Ark job ID and
   the provider `task_id` together before polling.
2. Poll `hyper3d_get_task` / `hitem3d_get_task` with `persist_output: false`
   every 5 s until terminal.
3. On success, poll again in the background with `persist_output: true`; the
   24 h file URL (a zip package) is copied into the artifact store.
4. After a local timeout, resume the same task ID; never submit a replacement.
5. A `failed` task with `AbilityProcessingError` is usually transient; resubmit
   the same request.
6. `hyper3d_list_tasks` / `hitem3d_list_tasks` (`page` 1–500, `page_size`
   1–100, `status`, `task_ids`, `model`; last 7 days) and
   `hyper3d_cancel_or_delete_task` / `hitem3d_cancel_or_delete_task`
   (`mode`, `expected_status`, `confirm: true`; cancel when `queued`, delete
   when `succeeded`, `failed`, or `expired`) work like the Seedance
   equivalents. Delete only with explicit cleanup scope.

The get tools return `task_id`, `model`, timestamps, `status`, optional
`error`, optional `file` (`ArtifactRef`), and optional `usage`.

## Delivery contract

Provider success delivers a generated package, not a DCC-ready or approved
asset.

- Retain the immutable package. Record the family and model, request and
  reference hashes, the Ark job ID and provider task ID as separate values,
  artifact ID, bytes, package SHA-256, requested format, material and topology
  settings, usage, and source URL expiry.
- Prefer GLB for an initial Blender handoff so mesh, hierarchy, materials, and
  textures travel together.
- Extract into a new bounded directory; reject absolute paths and parent
  traversal; never overwrite the provider archive.
- A generated 3D asset supplies structure and appearance. It becomes a
  Seedance motion authority only when an animated render is intentionally
  selected and bound for a supported video-reference mode. Keep 3D generation,
  normalization, previz rendering, and Seedance generation as distinct
  operations with distinct IDs, costs, statuses, and review evidence.

## Post-generation 3D QA

1. Validate package type, bytes, and SHA-256; preserve the original archive.
2. Inspect archive paths before extraction; confirm the requested format
   exists.
3. Import into an isolated quarantine collection; record object, mesh, face,
   material, texture, UV, and armature counts.
4. Measure dimensions, units, axes, origin, transforms, normals, non-manifold
   geometry, missing textures, and rig readiness. A package that imports at the
   wrong scale or without materials usually reflects unit, axis, format, or
   texture assumptions; normalize a working copy.
5. Save the normalized working copy and viewport evidence without mutating the
   provider artifact; record its hash separately.
6. Set the asset to `review`. Provider success and a clean import do not
   establish approval.
