## Default writing workflow

Unless the user specifies otherwise, follow this sequence:

1. Identify the target audience, use case, and desired business takeaway.
2. Gather the prompts, results, and any example structure the user wants to emulate.
3. If the showcase has 2+ approved scene videos, assemble them into one
   compilation highlight with `ffmpeg-scene-transitions` and verify it (see the
   "Highlight video compilation" subsection). An explicit user request to add
   another existing video authorizes that placement but does not change its
   approval state.
4. Normalize the material into external-facing language.
5. Create the Lark document structure.
6. Add the **Production Overview & Capabilities Matrix** and the **Highlight
   Video** (playable compilation or hero clip) near the top, right after the
   title — outcome first.
7. Add a concise executive summary and workflow overview.
8. For a multi-project commercial showcase, build one project section at a
   time: `Elements` first, then `Videos` only when that project has video to
   show. Use the project table headers and widths from the project layout
   reference.
9. Otherwise, build the **input assets table** with reference images and their prompts as a column (Table-first layout, principle 1).
10. Build **audio assets table** (if applicable) as a single consolidated table with a Scene column (Table-first layout, principle 2).
11. Build one **scene-by-scene table** per scene with prompt + generated result side by side; consolidate into a single table when scenes share the same structure.
12. Add a conclusion section.
13. Fetch the final structure, compare it with the pre-write inventory, and verify no internal path or local-file wording remains.
